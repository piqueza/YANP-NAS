# Pre-publication audit — YANP Nas 0.2.0

Date: 31 October 2026. Scope: the source, standalone release folder and generated
source archive intended for GitHub publication, plus targeted runtime checks of
authentication, authorization, credential handling and web-file boundaries.

Follow-up review, **2 November 2026**: [RELEASE_QA.md](RELEASE_QA.md) records the
current first-publication decision, 105 unit/native tests, 46 integration checks,
native configuration results, an extended identity scan and zero Gitleaks
findings. The refreshed export and archive exclude runtime artifacts.

## Personal and identifying information

No maintainer name, email address, workstation hostname, actual NAS address or
personal workstation path was found in the source text or source archive.
The scan included hidden release files and binary artifacts.

**Fixed:** 22 Python bytecode caches in the standalone release folder contained
the local workstation path, including its login name. They were generated by a
test run after the original source archive had been produced. The archive already
excluded them. All caches were removed from the refreshed upload folder, and
verification now avoids generating bytecode there. Git also ignores such caches,
but a direct browser/file upload should use the cleaned export.

The source archive normalizes file ownership and timestamps rather than recording
the local account as its owner. Fictional test names and documentation/test IPs
are retained. GPL license notices identify the license's authors, not the maintainer.

## Secrets and passwords

No deployed administrator password, database password, setup token, signing key,
provider token, private key, runtime configuration or database dump was found in
the publication files. Production credentials are generated during installation.
The public schema contains no default administrator or default password.

Tests contain negative-login examples and synthetic fixtures. The fixed Argon2id
value in the login handler is a dummy verification hash for nonexistent users;
it is not an account credential. A matching password cannot authenticate without
an enabled database account. Test services use disposable, locally generated
credentials in private temporary directories, outside the release tree.

Runtime administrator passwords are hashed with Argon2id. PHP returns an explicit
user-field allowlist, and the agent's user list omits password hashes. Samba
passwords are supplied through stdin, not command arguments or persisted jobs.
Configuration and setup-token files are outside Apache's public directory.

**Fixed:** malformed synchronous management requests could reach audit logging
before schema validation. Validation now precedes audit writes, credential fields
are rejected recursively before queue persistence, and account synchronization
audits only the account ID. Firewall confirmation nonces are omitted from audit.

## Authentication and obvious web security issues

**Fixed:** background status/job polling renewed the session's inactivity timer.
Passive reads now leave it unchanged. Actual user activity renews a valid session;
an expired session cannot renew itself. The eight-hour absolute limit remains.

Password dialogs are cleared when closed, including Escape, logout and expiration.
Cached administrator view state is cleared on logout/expiration; responses from
a previous session are discarded rather than restoring stale views.

Tests verify that anonymous/standard clients cannot reset administrator passwords,
promote themselves or invoke privileged management operations. Socket requests
have their own role checks, freshness and replay checks. Server-side SQL uses
parameters; management commands use allowlisted operations and argument arrays.
Rendered values are escaped and the interface has a same-origin CSP.

## Verification

- **55 unit/native tests passed**, including publication scanning and audit handling.
- **39 isolated PHP/MariaDB/socket integration checks passed**, including actual
  credential/hash absence from API responses and audit/job/event records,
  password-reset denial, idle expiration, CSRF and role enforcement.
- Native Apache checks served HTTPS and rejected private source/configuration/Git
  and traversal URLs. A PHP development-server fallback was also checked to return
  only the identical public index, never private contents.
- Apache/Fail2ban configuration and source syntax checks passed.
- The refreshed release folder and archive were scanned again for identifying
  strings, credential patterns, private files and generated artifacts.

Run `python3 -B scripts/check_publication.py` inside a release checkout before
uploading it. Optional `--identity` arguments add private names/emails/hostnames
to the scan without printing matching values. The packager runs the same checks
on its allowlisted inputs before creating a source archive.

## Limits

The subsequent existing-partition/NTFS feature build was scanned again with no
publication findings. Its 78 unit/native tests and 39 integration checks pass.
The fixed NTFS mapping SID is public, synthetic policy data, not an account
identity or secret. The source packager and refreshed standalone folder exclude
all bytecode. NTFS/FUSE hardware acceptance remains recorded in [VALIDATION.md](VALIDATION.md).

The user/share workflow follow-up passes 89 unit/native tests and 39 isolated
integration checks. Samba passwords entered in the combined form still use the
synchronous credential handler, never the job queue. Per-user access operations
accept only an account ID and directory/mode changes, and are administrator-only.
No form drafts are persisted for the new-tab workflow. Publication scanning of
the refreshed source/release reports no findings.

Root-console password recovery (2 November 2026) expands validation to 100
unit/native tests and 43 integration checks. The interactive script reads the
installed root-only agent configuration, passes new passwords to PHP through a
private stdin pipe, and stores Argon2id hashes in MariaDB. Passwords and hashes
are excluded from its audit/events and terminal output. No plaintext recovery
file or default password was added to the source release.

This is a focused code/publication review with targeted tests, not an independent
penetration test or proof of absence of vulnerabilities. It does not inspect an
installed NAS's live configuration or independently verify hardware operations.
The local release Git repository had no commits or remotes; future Git author
metadata and GitHub profile information are outside the exported-file scan.
The first-test-release status and target-server checklist still apply.
